# Прогнозно-аналитическая система мониторинга и прогнозирования загрузки городских парковочных пространств

## Описание проекта

Проект посвящён разработке системы для мониторинга и прогнозирования уровня загрузки городских парковочных пространств.

## Цель проекта

Создание системы, которая собирает данные о состоянии парковок, анализирует динамику загрузки и прогнозирует будущую занятость парковочных мест.

## Источники данных

- Open Data Hub Mobility API;
- Open-Meteo API;
- календарные данные.

## Этап разработки

Постановка задачи и подготовка структуры проекта.

## Запуск загрузки данных

Требуется Python 3.10 или новее. Используется только стандартная
библиотека Python, установка дополнительных пакетов не требуется.

Команды выполняются из главной папки проекта.

### Получение проекта

```bash
git clone https://github.com/ldlddaa/parking-occupancy-forecast-system.git
cd parking-occupancy-forecast-system
```

При работе в Codespaces этого репозитория клонирование не требуется.

### Обновление данных

```bash
python src/update_parking.py --until 2026-10-03
python src/update_weather.py --until 2026-10-03
```

Параметр `--until` задаёт конечную дату, не включая её.
В примере загружаются данные по 2 октября 2026 года включительно.

Если период уже загружен, запросы к API не выполняются.
Для догрузки следующих суток нужно указать более позднюю дату,
за которую источники уже предоставляют исторические данные.

Накопленные данные и границы загрузки находятся в:
- `data/storage/parking.json`;
- `data/storage/weather.json`.

При отсутствии накопительных файлов загрузчики используют
сентябрьские выгрузки из `data/raw` как начальные данные.

### Настройки запросов

Через переменные окружения можно изменить:
- `HTTP_TIMEOUT` — время ожидания ответа, по умолчанию 45 секунд;
- `HTTP_ATTEMPTS` — максимальное число попыток, по умолчанию 3.

Пример для терминала Bash:

```bash
HTTP_TIMEOUT=30 HTTP_ATTEMPTS=3 python src/update_parking.py --until 2026-10-03
```

### Проверки

```bash
python src/check_idempotency.py
python src/check_resilience.py
python src/check_load_log.py
```

Проверяются повторная обработка без дублей, поведение при сетевых
ошибках, сохранность данных при сбое и регистрация ошибок в журнале.
Проверки выполняются без настоящих запросов к API.

`check_load_log.py` добавляет в журнал тестовые записи об ошибках.
Они помечены соответствующим текстом в поле `error`.

### Журнал загрузок

Журнал основных загрузчиков сохраняется в `logs/load_log.csv`.
Он содержит источник, параметры запуска, время выполнения,
количество записей и границы загрузки до и после запуска,
статус и описание ошибки.

## Обработка данных и построение витрины

После загрузки исходных данных запустите из корня проекта:

```bash
python src/run_processing.py
```

Команда последовательно выполняет семь этапов:

1. Проверка структуры входных данных.
2. Проверка справочника парковок.
3. Очистка и преобразование парковочных данных.
4. Очистка и преобразование погодных данных.
5. Объединение данных в аналитическую витрину.
6. Проверка структуры всех таблиц.
7. Проверка качества витрины.

Обработка использует накопленные данные из `data/storage/`.
Запросы к внешним API не выполняются.
При ошибке выполнение следующих этапов прекращается.

### Настройки

- `config/processing.json` — правила обработки и сопоставления данных.
- `config/schemas.json` — обязательные поля и ожидаемые столбцы.
- `data/reference/parkings.csv` — справочник парковок и вместимости.
- `docs/data_architecture.md` — описание слоёв хранения.

### Результаты

- `data/processed/parking_clean.csv` — подготовленные парковочные данные.
- `data/processed/weather_clean.csv` — подготовленные погодные данные.
- `data/processed/*_rejected.csv` — отклонённые записи с причинами.
- `data/marts/parking_weather.csv` — аналитическая витрина.
- `logs/quality/` — отчёты о структуре и качестве данных.
- `logs/processing_run.json` — результат последнего запуска обработки.

### Проверка реакции на изменение структуры

```bash
python src/check_schema_changes.py
```

Проверка выполняется на временных файлах и не изменяет данные проекта.

### Ограничения данных

Пропущенные наблюдения не заменяются нулями.
Парковочные отметки вне пятиминутной сетки сохраняются с признаком качества.
Историческая неизменность вместимости парковок не подтверждена;
это ограничение отмечается в подготовленных данных.

Погода сопоставляется по последней временной отметке, не превышающей
время парковочного наблюдения, с допустимым возрастом до 60 минут.
Исторические погодные данные не подтверждают доступность этих значений
в момент реального прогнозирования.

## Анализ, прогнозирование и дашборды

Этап прогнозирования использует сторонние библиотеки из requirements.txt.
Проект выполнялся на Python 3.14.2.

### Установка зависимостей

Из корня проекта:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Если окружение уже создано, достаточно активировать его и установить зависимости.

### Воспроизведение расчётов

При наличии накопленных данных в data/storage/ выполнить по порядку:

```bash
python src/run_processing.py
python src/analyze_parking.py
python src/prepare_forecast_targets.py
python src/prepare_features.py
python src/train_models.py
python src/evaluate_models.py
python src/plot_forecasts.py
```

Горизонт прогноза — 60 минут. Выборки разделены хронологически:
обучение — 1–20 сентября, валидация — 21–26 сентября,
тестирование — 27 сентября – 2 октября 2026 года. Границы заданы по UTC.

Настройки находятся в config/forecasting.json, config/features.json
и config/models.json. Погодные признаки отключены.

Для каждой парковки обучаются линейная регрессия и случайный лес.
Настройки и модель выбираются по валидационной MAE.
Тестовые данные используются только для итоговой оценки.
Простой прогноз сохраняет текущую загрузку на следующий час.

### Результаты

- reports/analysis/ — описательная статистика и графики загрузки;
- data/modeling/ — целевые значения и признаки;
- models/ — обученные модели и описание запуска;
- reports/models/ — метрики, тестовые прогнозы и графики;
- logs/quality/ — отчёты подготовки и контроля качества.

На тесте выбранная линейная регрессия для парковки 103 уступила
простому прогнозу по MAE на 18,19%. Для парковки 106 выбранный
случайный лес снизил MAE на 25,86%. После тестирования выбор
моделей не изменялся.

### Запуск дашбордов

Предметный дашборд:

```bash
python -m streamlit run src/dashboard.py --server.address 0.0.0.0 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

Операционный дашборд — в отдельном терминале с активированным окружением:

```bash
python -m streamlit run src/operational_dashboard.py --server.address 0.0.0.0 --server.port 8502 --server.headless true --browser.gatherUsageStats false
```

В Codespaces открыть соответствующий порт через вкладку PORTS.
Дашборды читают сохранённые файлы проекта и не запрашивают внешние API.
Прогнозы отображаются для исторического тестового периода.

Ограничения: короткий период наблюдений, пропуски временных отметок
и неподтверждённая историческая неизменность вместимости парковок.
